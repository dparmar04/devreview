# T-001 - Environment, package skeleton, smoke test

## What it is
A **virtual environment** is a private, disposable folder of Python libraries for one project, so two projects never fight over versions. A **package** is a folder of code Python can import by name (`import devreview`). A **test** is a tiny program that checks one fact automatically and shouts if the fact stops being true.

Analogy: the virtual environment is a toolbox that belongs to this house only. The package is the labelled drawer in it. The test is the smoke alarm in that drawer.

## What I built here
DevReview has no code yet. This task creates the empty-but-importable shell that every later phase will live inside:
- `.venv/` - the project's private toolbox (git-ignored).
- `src/devreview/__init__.py` - the package, holding only a version number `0.0.0`.
- `tests/test_smoke.py` - one test proving the package imports and reports that version.
- Installed the package itself in "editable" mode plus the approved dev tools (pytest, ruff, bandit, pip-audit, pre-commit) from `pyproject.toml`.

Why it matters: later tasks add real features. If the smallest possible package plus one test cannot go green, every later "it works" claim is worthless. The version string is also the thing a release will bump in Phase 4.

## How it works
1. `python -m venv .venv` copies a mini Python plus its own `pip` into `.venv`.
2. `.venv/Scripts/python.exe` is now *this* project's Python. Anything installed with it stays inside `.venv`.
3. `pip install -e ".[dev]"` reads `pyproject.toml`, installs the `dev` optional dependency group, and links `src/devreview` into the environment ("editable" = it points at the source file, so edits take effect immediately).
4. `pytest` finds every `tests/test_*.py`, imports it, calls every function starting with `test_`, and reports pass/fail.
5. `assert devreview.__version__ == "0.0.0"` is the whole test: if the value changes without a deliberate update, it fails.

## What could go wrong
- **Ran `pytest` with the system Python instead of `.venv`'s**: `ModuleNotFoundError: No module named 'devreview'`. You would notice the error says `No module named devreview`. Fix: use `.\.venv\Scripts\python.exe` or activate the venv first.
- **Venv folder deleted or recreated**: the editable install disappears; the same `ModuleNotFoundError` returns. Fix: re-run the install command.
- **Version bumped in code but not in the test**: the smoke test goes red. That is intended: a version change should be a deliberate edit in two places, or the test should be rewritten to match the new contract.
- **Wrong Python version**: `requires-python = ">=3.11"`; this machine has 3.14.7, so it is satisfied. On an older interpreter pip would refuse to build.
- **Skipped the test-first step**: the failure would be for the wrong reason. It was checked: before the install the import failed with exactly `ModuleNotFoundError: No module named 'devreview'`.
