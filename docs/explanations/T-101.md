# T-101 - CLI skeleton

## What it is
A CLI (command-line interface) is a way to run your program by typing a command in the terminal — like how you type `npm start` to run a Node app. `argparse` is Python's built-in library for parsing those commands and flags (similar to how `commander` or `yargs` work in Node).

## What I built here
The `devreview` command that you can type in the terminal. Right now it does three things:
- `devreview --version` prints the version number
- `devreview dataset` is a placeholder group for future commands that build test datasets from git history
- `devreview backtest` is a placeholder group for future commands that run LLM reviews

DevReview needs this because every later feature (building datasets, running backtests) will be triggered through this CLI.

## How it works
1. `pyproject.toml` declares a **console script entry point**: `devreview = "devreview.cli:main"`. When pip installs the package, it creates a `devreview.exe` wrapper in the venv's `Scripts/` folder that calls the `main()` function.
2. `cli.py` builds an `ArgumentParser` with `--version` and two subcommands (`dataset`, `backtest`).
3. `__main__.py` lets you also run `python -m devreview` (Python looks for `__main__.py` inside a package when you use `-m`).
4. When you type `devreview dataset --help`, argparse routes to the `dataset` sub-parser and prints its help text.
5. When no subcommand is given, `main()` prints the top-level help.

## How to see it working
```
devreview --version
```
Expected output:
```

```

```

```

```

  -h, --help  show this help message and exit
```

## What could go wrong
- **"devreview not found"**: The venv isn't activated, or the package wasn't reinstalled after adding the entry point. Fix: activate venv and run `pip install -e ".[dev]"`.
- **Version shows wrong number**: `__version__` in `__init__.py` and `version` in `pyproject.toml` are separate. If someone changes one but not the other, they drift. The CLI reads from `__init__.py`.
